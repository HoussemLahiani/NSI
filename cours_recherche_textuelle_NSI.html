La recherche textuelle, c'est quoi ?

Programme officiel NSI Terminale — thème "Algorithmique" : algorithmes de recherche de motif.

🔍 Un problème du quotidien

Tu utilises la recherche textuelle chaque jour sans le savoir : Ctrl+F dans un document, la barre de recherche de ton navigateur, Google qui cherche tes mots dans des milliards de pages, ton téléphone qui cherche un contact dans ta liste...

💡 Le problème en une phrase : On a un texte (long) et on cherche un motif (court). On veut savoir à quelle(s) position(s) le motif apparaît dans le texte.

⚖️ Les 3 algorithmes au programme

AlgorithmeIdée principaleComplexité pire casÀ retenir
Naïf Essaye toutes les positions une par une O(n×m) Simple mais lent
Boyer-Moore-Horspool Saute des positions en cas d'échec O(n/m) en moy. Très rapide en pratique

L'algorithme naïf

La méthode la plus évidente — comme chercher dans un annuaire page par page.

💡 L'analogie du livre

Ton approche naturelle

Tu cherches "soleil" dans un livre. Tu commences à la page 1, tu regardes chaque mot. Si ça ne correspond pas, tu avances d'un mot et tu recommences. Tu ne sautes rien.

Le problème

Si le livre fait 500 pages et que "soleil" n'y est pas, tu as lu 500 pages pour rien. C'est la même chose pour l'algorithme naïf : il ne "profite" jamais de ses erreurs.

📐 Comment ça marche — étape par étape

Principe : Pour chaque position i dans le texte (de 0 à n-m), on compare le motif avec le texte à partir de i. Si toutes les lettres correspondent → trouvé ! Sinon → on avance de 1 seul position.
  1. Poser le motif sur le texte à la position i = 0
  2. Comparer lettre par lettre (j = 0, 1, 2... jusqu'à m-1)
  3. Si toutes les lettres correspondent : on a trouvé !
  4. Si une lettre diffère : avancer de 1 (i = i + 1) et recommencer en 2
  5. Si i > n - m : motif non trouvé

⚠️ Le défaut majeur

Exemple critique : texte = "AAAAAAAAAB" (9 A puis 1 B), motif = "AAAB". À chaque position, on compare 3 'A' avant de tomber sur la différence. On le fait 7 fois → 7×3 = 21 comparaisons inutiles. On n'a rien appris de nos échecs.

Complexité : O(n × m) dans le pire cas. Pour un texte de 1 million de caractères et un motif de 100 caractères → jusqu'à 100 millions de comparaisons.

Boyer-Moore-Horspool

Lire de droite à gauche et sauter des positions — l'algorithme le plus rapide en pratique.

💡 L'analogie du mot croisé

L'idée astucieuse

Tu cherches "CHAT" dans une grille. Tu regardes la dernière lettre d'abord. Si tu vois un 'Z' sous le motif, tu sais que 'Z' n'est pas dans "CHAT" → tu peux sauter 4 cases d'un coup !

Le gain

Au lieu d'avancer de 1 à chaque fois, tu avances parfois de m cases (toute la longueur du motif). En pratique, c'est souvent 5 à 10 fois plus rapide que l'algorithme naïf.

📊 La table de décalage (bad character table)

Avant de chercher, on construit une table qui dit : "Si je vois ce caractère, de combien est-ce que je dois décaler le motif ?"

Règle : Pour chaque caractère c du motif :
• Décalage = distance depuis la droite (dernière occurrence ≠ dernière position)
• Si le caractère n'est pas dans le motif → décalage = longueur du motif

Knuth-Morris-Pratt (KMP)

L'algorithme le plus élégant : ne jamais relire ce qu'on a déjà lu.

💡 L'analogie du détective

Le principe

Quand tu lis "ABCAB" et que la 6ᵉ lettre diffère, tu sais que tu as déjà vu "AB" au début. Tu n'as pas besoin de revenir en arrière dans le texte : tu repars simplement du bon endroit dans le motif.

La clé

KMP ne recule jamais dans le texte. Il avance toujours. C'est pour ça que sa complexité est O(n+m) — on lit chaque caractère au plus une fois.

🔧 La table des échecs (failure function)

Avant de chercher, KMP construit une table f pour le motif. f[j] dit : "Si le j-ème caractère du motif diffère, recommence la comparaison à partir de f[j]."

Ce que fait f[j] : c'est la longueur du plus long préfixe propre du motif[0..j] qui est aussi un suffixe. Dit autrement : combien de lettres du début du motif j'ai déjà "validées" malgré l'échec.

Le code Python

Chaque algorithme écrit en Python, commenté ligne par ligne.

💡 L'algorithme naïf : deux boucles imbriquées. La boucle externe parcourt toutes les positions du texte. La boucle interne compare lettre par lettre.
# ─── Recherche naïve ───────────────────────────────

def recherche_naive(texte, motif):
    n = len(texte)   # longueur du texte
    m = len(motif)   # longueur du motif
    occurrences = [] # liste des positions trouvées

    # On essaie toutes les positions possibles
    # i va de 0 à n-m  (inutile d'aller plus loin)
    for i in range(n - m + 1):

        j = 0  # indice dans le motif

        # On compare lettre par lettre
        while j < m and texte[i + j] == motif[j]:
            j += 1   # lettre suivante

        # Si j == m, on a comparé toutes les lettres → trouvé !
        if j == m:
            occurrences.append(i)

    return occurrences

# Test
texte  = "ABRACADABRA"
motif  = "ABRA"
print(recherche_naive(texte, motif))  # → [0, 7]
📌 Complexité : O(n × m) dans le pire cas. Les deux boucles imbriquées : la externe fait n-m+1 itérations, l'interne peut faire jusqu'à m comparaisons.
💡 BMH : 1) Construire la table de décalage. 2) Comparer de droite à gauche. 3) En cas d'échec, utiliser la table pour sauter plusieurs positions.
# ─── Boyer-Moore-Horspool ──────────────────────────

def table_decalage(motif):
    """Construit la table 'bad character' de BMH"""
    m = len(motif)
    table = {}  # dictionnaire : caractère → décalage

    # Pour chaque caractère du motif SAUF le dernier
    for i in range(m - 1):
        table[motif[i]] = m - 1 - i  # distance à la fin

    # Caractère absent du motif → décalage = m (longueur totale)
    # On utilise m comme valeur par défaut
    return table

def boyer_moore_horspool(texte, motif):
    n = len(texte)
    m = len(motif)
    table = table_decalage(motif)
    occurrences = []

    i = 0  # position de départ de la fenêtre

    while i <= n - m:
        j = m - 1  # on commence par la DROITE du motif

        # Comparaison de droite à gauche
        while j >= 0 and texte[i + j] == motif[j]:
            j -= 1

        if j < 0:
            occurrences.append(i)    # motif trouvé !
            i += 1
        else:
            # Caractère du texte aligné avec la fin du motif
            c = texte[i + m - 1]
            decalage = table.get(c, m)  # m si caractère absent
            i += max(1, decalage)

    return occurrences

# Test
print(boyer_moore_horspool("ABRACADABRA", "ABRA"))  # → [0, 7]
💡 KMP : 1) Construire la table des échecs. 2) Chercher sans jamais reculer dans le texte. En cas d'échec, utiliser f[j] pour savoir où reprendre.
# ─── Knuth-Morris-Pratt (KMP) ──────────────────────

def table_echecs(motif):
    """Construit la failure function de KMP"""
    m = len(motif)
    f = [0] * m     # f[j] = longueur du plus long bord de motif[0..j]
    k = 0           # longueur du bord courant

    for j in range(1, m):
        while k > 0 and motif[j] != motif[k]:
            k = f[k - 1]        # recul dans le motif
        if motif[j] == motif[k]:
            k += 1              # extension du bord
        f[j] = k
    return f

def kmp(texte, motif):
    n = len(texte)
    m = len(motif)
    f = table_echecs(motif)
    occurrences = []

    j = 0  # indice dans le motif

    for i in range(n):   # i parcourt le texte (jamais de retour en arrière !)

        while j > 0 and texte[i] != motif[j]:
            j = f[j - 1]       # utilise la table des échecs

        if texte[i] == motif[j]:
            j += 1             # caractère validé

        if j == m:             # motif entier trouvé
            occurrences.append(i - m + 1)
            j = f[j - 1]       # pour chercher d'autres occurrences

    return occurrences

# Test
print(kmp("ABABABABAC", "ABABAC"))  # → [4]
✅ Complexité : O(n + m). La boucle principale fait exactement n iterations (i ne recule jamais). La construction de la table fait O(m). C'est l'algorithme optimal en théorie.
