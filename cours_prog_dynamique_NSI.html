Qu'est-ce que la programmation dynamique ?

Comprenons le problème avant de chercher la solution.

🎯Le problème de base

Imagine que tu dois calculer fib(30) — le 30ᵉ nombre de Fibonacci. Sans technique spéciale, ton programme va faire plus de 2 millions de calculs… dont la plupart sont les mêmes calculs répétés.

⚠️ Le vrai problème : Ce n'est pas la récursivité qui est lente. C'est le fait de recalculer la même chose des milliers de fois alors qu'on l'a déjà calculé avant.
💡Analogie de la vie réelle

Imaginons que tu prépares des crêpes. La recette demande "combien de litres pour 10 personnes ?". Tu calcules : 2 litres.

❌ Sans mémoïsation (stupide)

La 2ᵉ fois qu'on te demande "combien pour 10 personnes ?", tu recommences tous les calculs depuis le début. Et la 3ᵉ fois. Et la 4ᵉ fois...

✓ Avec mémoïsation (intelligent)

Tu notes la réponse sur un papier. La 2ᵉ fois, tu lis juste le papier. Zéro calcul. Instantané.

🎯 La programmation dynamique, c'est ça : noter les résultats intermédiaires pour ne jamais les recalculer.

La mémoïsation — expliquée simplement

Le mot fait peur, l'idée est évidente. Voyons ça ensemble.

📖Le mot "mémoïsation"
Mémoïsation vient de l'anglais memoize, lui-même dérivé du latin memoria (mémoire). Ça veut dire : enregistrer (mémoriser) le résultat d'une fonction pour ne pas avoir à le recalculer.

👉 C'est différent de "mémorisation" (apprendre par cœur). Ici c'est le programme qui se souvient, pas toi.
🧊Analogie : le frigo-bloc-notes

Imagine que quelqu'un te demande chaque matin : "Quelle est la température du frigo ?". Tu peux :

❌ Sans mémo

Ouvrir le frigo, lire le thermomètre, fermer le frigo. À chaque fois.

✓ Avec mémo

La 1ʳᵉ fois tu lis, et tu notes sur un post-it. Ensuite tu lis le post-it. 10 fois plus rapide.

Le problème du sac à dos

Le problème classique de l'examen NSI — décomposé en étapes ultra-simples.

🎒Comprendre le problème

Tu as un sac qui peut porter maximum 5 kg. Tu veux emporter des objets pour maximiser la valeur totale. Chaque objet peut être pris ou non (pas de demi-objet).

ObjetPoidsValeurRatio V/P
🍎 Objet A2 kg3 €1.5 €/kg
📚 Objet B3 kg4 €1.33 €/kg
💎 Objet C4 kg5 €1.25 €/kg
⚠️ Pourquoi pas l'algorithme glouton ? Si on prend le meilleur ratio (A=1.5), on prend A(2kg) puis B(3kg) = 5kg = 7€. Ici ça marche, mais ce n'est pas toujours optimal ! La prog. dynamique donne toujours la réponse optimale.
📐L'idée du tableau 2D

On construit un tableau où :

  • Ligne i = on considère les i premiers objets
  • Colonne w = la capacité du sac est de w kg
  • Case dp[i][w] = valeur maximale avec les i premiers objets dans un sac de w kg
💡 La formule :
• Si on ne prend pas l'objet i : dp[i][w] = dp[i-1][w]
• Si on prend l'objet i (si possible) : dp[i][w] = dp[i-1][w - poids[i]] + valeur[i]
• On garde le maximum des deux.

Le code Python commenté

Chaque ligne expliquée comme si tu n'avais jamais codé.

💡 Top-down : On part du problème global (fib(n)) et on descend vers les petits cas. On stocke les résultats dans un dictionnaire memo pour ne pas les recalculer.
# ─── Fibonacci : approche Top-down (mémoïsation) ───

# Le dictionnaire memo est notre "carnet de notes"
# memo[n] = résultat de fib(n), si déjà calculé
memo = {}

def fib(n):

    # ÉTAPE 1 : Est-ce qu'on a déjà calculé fib(n) ?
    if n in memo:
        return memo[n]    # OUI → on lit dans le carnet, on ne recalcule pas

    # ÉTAPE 2 : Cas de base (on connaît les réponses par définition)
    if n == 0:
        return 0
    if n == 1:
        return 1

    # ÉTAPE 3 : Calcul (appels récursifs)
    resultat = fib(n-1) + fib(n-2)

    # ÉTAPE 4 : On note dans le carnet avant de retourner
    memo[n] = resultat

    return resultat

# Test
print(fib(10))  # → 55
print(fib(30))  # → 832040 (instantané grâce à la mémoïsation !)

💡 Bottom-up : On part des petits cas (fib(0), fib(1)...) et on monte. On utilise une liste Python au lieu de la récursivité.
# ─── Fibonacci : approche Bottom-up (tableau) ───

def fib(n):
    # Cas simples
    if n <= 1:
        return n

    # ÉTAPE 1 : Créer le tableau (liste de n+1 zéros)
    # dp[i] contiendra la valeur de fib(i)
    dp = [0] * (n + 1)   # ex pour n=5 : [0, 0, 0, 0, 0, 0]

    # ÉTAPE 2 : Initialiser les cas de base
    dp[0] = 0             # F(0) = 0 par définition
    dp[1] = 1             # F(1) = 1 par définition

    # ÉTAPE 3 : Remplir le tableau de gauche à droite
    for i in range(2, n + 1):
        dp[i] = dp[i-1] + dp[i-2]   # formule de récurrence

    # ÉTAPE 4 : La réponse est dans la dernière case
    return dp[n]

# Test
print(fib(10))  # → 55
Astuce mémoire : En fait, pour Fibonacci on n'a besoin que des 2 dernières cases. On peut optimiser avec a, b = b, a+b. Mais pour l'examen, la version avec le tableau complet est plus lisible et toujours acceptée.
💡 Sac à dos : Tableau 2D. Chaque case dp[i][w] répond à la question : "Quelle est la valeur max avec les i premiers objets et un sac de w kg ?"
# ─── Sac à dos 0/1 — Bottom-up ───

def sac_a_dos(objets, capacite):
    # objets = liste de tuples (poids, valeur)
    # ex : [(2,3), (3,4), (4,5)]

    n = len(objets)   # nombre d'objets

    # ÉTAPE 1 : Créer le tableau 2D rempli de zéros
    # dp[i][w] = valeur max avec i objets, capacité w
    dp = [[0] * (capacite + 1) for _ in range(n + 1)]

    # ÉTAPE 2 : Remplir le tableau
    for i in range(1, n + 1):
        poids_i  = objets[i-1][0]   # poids de l'objet i
        valeur_i = objets[i-1][1]   # valeur de l'objet i

        for w in range(capacite + 1):

            # Option 1 : on ne prend PAS l'objet i
            sans_i = dp[i-1][w]

            # Option 2 : on prend l'objet i (si le sac est assez grand)
            avec_i = 0
            if w >= poids_i:
                avec_i = dp[i-1][w - poids_i] + valeur_i

            # On garde la meilleure option
            dp[i][w] = max(sans_i, avec_i)

    # ÉTAPE 3 : La réponse est en bas à droite
    return dp[n][capacite]


# Test avec nos objets
objets = [(2, 3), (3, 4), (4, 5)]
print(sac_a_dos(objets, 5))  # → 7
